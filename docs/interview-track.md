# Interview Track

## Entry criteria

- Most familiar Easy problems are solved in 20–25 minutes.
- Familiar Medium problems are usually solved in 35–45 minutes.
- Binary search, BFS, DFS, heap operations, backtracking, and core DP states can be written without copying templates.
- The learner can explain brute force, optimization, correctness, complexity, and edge cases.

## Interview answer sequence

1. Clarify the problem and constraints.
2. Create examples and edge cases.
3. Present a simple baseline.
4. Identify the bottleneck.
5. Propose and justify the optimized approach.
6. Code while keeping the interviewer oriented.
7. Dry-run important cases.
8. State time and space complexity.

## Mock cadence

- Months 7–12: one light mock per month.
- Months 13–18: one mock every two to four weeks.
- Months 19–21: two mocks per month.
- Months 22–24: one mock per week when possible.

The readiness target is two Medium problems in roughly 70–90 minutes while communicating clearly. It is a training target, not a universal hiring rule.

## Python transition set

Rewrite familiar solutions—not new algorithms—in Python. A useful representative set is:

`1`, `125`, `3`, `20`, `206`, `102`, `215`, `200`, `207`, `78`, `56`, `322`.

After several mocks, select the language with fewer implementation errors and more consistent completion time.
